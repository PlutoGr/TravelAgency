# Шаблон коммитов и PR

Коммиты и PR пишутся по-русски, как мои собственные заметки: без «разработчик сделал»,
без тегов ролей (`[Разработчик]`, `[Продакт]`, `[DevOps]`) и без имён ассистентов.
Технические идентификаторы (имена классов, эндпоинты, пакеты) остаются как есть.

## Заголовок

```
<тип>(<сервис>): <что сделано, кратко>
```

Для squash/merge-коммита PR в конце добавляется номер: ` (#NN)`.

**Типы:** `разработка`, `исправление`, `тесты`, `аналитика`, `инфраструктура`,
`зависимости`, `документация`.

**Сервис** — по затронутым файлам: `чат`, `каталог`, `бронирование`, `identity`, `медиа`,
`шлюз`, `фронт`, `ci`, `деплой`, `бд`, `общее` (если затронуто несколько сервисов).

## Тело (необязательно для мелких коммитов)

```
Зачем: <какую проблему решаю>
Как работает: <коротко, что поменялось>
Задача: #NN
```

Трейлеры `Co-authored-by` для ботов и ассистентов не добавляются.

## Примеры

```
исправление(медиа): подпись тела файла при загрузке в MinIO по HTTP (#60)

Зачем: на dev POST /media/upload отвечал 500 на любой файл.
Как работает: DisablePayloadSigning включается только для https, по http тело подписывается.
Задача: #59
```

```
разработка(каталог): публичная выдача туров (#61)
```

```
инфраструктура(ci): проверка PR без деплоя, actions закреплены по SHA
```

```
зависимости(фронт): обновить vitest и tinypool
```

Dependabot сам ставит префикс `зависимости` (см. `.github/dependabot.yml`).

## PR

Шаблон — `.github/pull_request_template.md`. Заголовок PR совпадает с заголовком
коммита без номера. Обязательные разделы: «Что сделано», «Зачем», «Как это работает»
(начиная с простого примера), «Учебный кейс». Затем «Как проверить» и «Задача: closes #NN».

## Секреты

Репозиторий публичный: всё, что попало в коммит, PR, issue, комментарий или вики, видно всем
и остаётся в истории навсегда.

**Никогда не коммитить и не писать в PR, issue, комментарии и вики:**
- пароли;
- токены (`ghp_`, `github_pat_`, `sk-`, `AKIA…` и любые другие);
- ключи подписи JWT и ключи gRPC;
- ключи MinIO и S3;
- строки подключения с паролем (`...;Password=...`);
- приватные ключи и сертификаты (`*.pem`, `*.key`, `*.pfx`, `id_rsa`, `id_ed25519`);
- файлы `htpasswd`;
- содержимое `.env`.

**Где живут значения:** только в `.env` на сервере, в GitHub Secrets и в `dotnet user-secrets`
на своей машине. В коде, примерах и документации пишем заглушки:
`Password=<POSTGRES_PASSWORD>`, `JwtSettings__SigningKey=<ключ>`.

**Перед push** проверяю:

```bash
gitleaks git --redact .
```

Тот же gitleaks запускается в CI на каждый PR (`.github/workflows/gitleaks.yml`,
правила в `.gitleaks.toml`). Фиктивные значения из тестов разрешаются точным значением
в `.gitleaks.toml`, а не исключением целой папки.

Кроме стандартных правил там есть своё `connection-string-password`: оно ловит
`Password=...` и `Pwd=...` в строках подключения. Не считаются паролем подстановки
(`${POSTGRES_PASSWORD}`, `%DB_PASSWORD%`), значения в угловых скобках (`<POSTGRES_PASSWORD>`)
и явные заглушки (`CHANGE_ME`, `REPLACE_...`, `your-...`, `...`). Слово вроде `postgres`
после `Password=` правило найдёт: это настоящий, хоть и слабый, пароль.

**Если секрет утёк:** сначала ротация (новый пароль или ключ на сервере и в GitHub Secrets,
старый отозван), потом удаление из кода. Удаление без ротации ничего не исправляет: старое
значение уже лежит в истории git, в форках и в кэшах.
