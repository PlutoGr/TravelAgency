# Weekly audit
Routine «Еженедельный аудит порядка», Monday 12:00 Europe/Moscow, by the orchestrator ([wake sources](events.md#wake-sources)). Goal: the FSM still delivers staged, tracked, closable work with order and throughput, and the project stays clean and secure. Refresh [memory](../elements/memory.md). A repo-side consistency pass over `.cursor/` may be delegated to a cloud agent with the [methodology auditor brief](../briefs/methodology-auditor.md). Monday audit is the backstop for owner re-asks, stalled agents and Deploy catch-up when no other wake ran; weekday memory-refresh remains a wake source.

## Checklist
1. **Board:** every open issue has exactly one `статус:*`; closed issues only `статус: готово`; no feature on `статус: в работе` or `статус: демо`; epics in В работе only while children are in flight; product epics with every child Готово are in Демо (not stuck in В работе, unless waiting on the owner to create Status «Демо», [stage 13](13-epic-acceptance.md)); Готово newest-first; Очередь top = current epic's children and the stated «Приоритет» ([board](../elements/board/README.md), [queue priority](../elements/board/queue-priority.md)). Status matches the label (orchestrator-owned; hygiene deleted / orchestrator-only). #8 stays `статус: очередь`. Never move an issue that is in Удержание; it leaves only on the recorded owner resume ([Удержание](../elements/board/columns/on-hold.md)).
2. **Tasks:** every open issue taken or edited since the last audit matches its template (others are brought to it when next taken); foreign-filed issues since last audit brought to template + single `статус:*` + Status = Очередь + «Приоритет»; no subtask or mini-feature; bug-features link their source feature; every Удержание has a hold comment that names what resumes it; every Очередь card has «Приоритет» (set missing ones), except Очередь children of an epic in Удержание, which stay unnumbered; no issue parked in another column for an owner question (questions = pause in place).
3. **Git and PRs:** active remote branches match `type/NN-short-english-slug` ([branches](../elements/git/branches.md)); clean orphans that will not auto-delete (deleting branches other than merged head branches needs the owner); no open PR without an owner and next step; recent PRs have `#NN`, a «Документация» line, finished finding replies; Dependabot rows recorded with `Issue` = `-`, `Stage` = `Dependabot`, PR and sha; a row still `CI+Automations` whose Automations are done is switched to `none` + full review and reviewed now. Do not retrofit closedBy on old closed issues.
4. **Wiki:** no `Doc-` page edited before `main`; no status line treated as truth; sidebar complete; Plan- pages current ([wiki](../elements/wiki/README.md)).
5. **Automations and routines:** every inventory row still Active (Bugbot scope = this repo only); the three routines «TravelAgency CI/CD», `travelagency-memory-refresh` and «Еженедельный аудит порядка» exist and are enabled (missing or disabled = blocker reported to the owner); spot-check 1-2 recent PRs; latest weekly vuln scan run history ([automations](../elements/automations.md)).
6. **Rules:** `.cursor/` consistent with practice; one way of doing each thing; templates match live artifacts.
7. **Memory** current; no hanging cloud agent; stale waits re-checked (agent silence, Deploy catch-up, Dependabot rows waiting on Automations); every row with `Waiting on` = `none` and a concrete `Next` is performed before the audit ends.
8. **Owner waits:** each pause with `Waiting on` = owner in memory is listed once in the report with the original question and recommendation (ask again if still unanswered; not a new question); an owner hold ([Удержание](../elements/board/columns/on-hold.md)) is listed with its resume condition and not re-asked.

## Output
Fix clear reversible drifts at once on work taken or edited since the last audit, and any wrong label, missing «Приоритет» (except children of a held epic) or missing hold reason anywhere ([orchestrator §6](../orchestrator.md#6-powers-act-and-report-vs-ask-first)); older off-template items follow the [in-flight rule](README.md#gates). Send the owner a short [weekly audit report](../templates/owner/weekly-audit-report.md) only when something needs a decision or was fixed that the owner should know; propose rule changes there.
