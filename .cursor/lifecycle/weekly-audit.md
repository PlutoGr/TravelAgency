# Weekly audit
Routine «Еженедельный аудит порядка», Monday 12:00 Europe/Moscow, by the orchestrator ([wake sources](events.md#wake-sources)). Goal: the FSM still delivers staged, tracked, closable work with order and throughput, and the project stays clean and secure. Refresh [memory](../elements/memory.md). A repo-side consistency pass over `.cursor/` may be delegated to a cloud agent with the [methodology auditor brief](../briefs/methodology-auditor.md). Monday audit is the backstop for owner re-asks, stalled agents and Deploy catch-up when no other wake ran; weekday memory-refresh remains a wake source.

## Checklist
1. **Board:** every open issue has exactly one `статус:*`; closed issues only `статус: готово`; no feature on `статус: аналитика`, `статус: архитектура`, `статус: в работе` or `статус: демо`; epics in В работе only while children are in flight; product epics with every child Готово follow the [epic demo](13-epic-acceptance.md) entry order (existing `Question` waits; missing Status «Демо» → `create Status «Демо»` and stay in В работе; otherwise Демо + `Question` = `epic demo`), unless the epic's `Question` is set (then it waits for that answer); Готово newest-first; Очередь top = current epic's children and the stated «Приоритет» ([board](../elements/board/README.md), [queue priority](../elements/board/queue-priority.md)). Status matches the label (orchestrator-owned; hygiene deleted / orchestrator-only). #8 stays `статус: очередь`. Never move an issue that is in Удержание; it leaves only on the recorded owner resume ([Удержание](../elements/board/columns/on-hold.md)). A feature past Очередь has `Размер`, `Вид` and `Тесты` on the issue and the Feature page, except an item already in Тест-кейсы, Разработка, Приёмка or Готово when this rule set took effect, which is not failed for a missing tag. The column matches the route: a feature whose policy is not Крупная + `сначала сценарии` is not on `статус: тест-кейсы`, except an item already in Тест-кейсы when this rule set took effect, which keeps that column ([in-flight](README.md#gates)); a feature in Разработка has «Тест-кейсы» on the page (a policy line or a short scenario list counts) ([test policy](05-epic-split.md#kind-and-test-policy)). A feature still on `статус: аналитика` or `статус: архитектура` is moved forward on the new route ([in-flight](README.md#gates)).
2. **Tasks:** every open issue taken or edited since the last audit matches its template (others are brought to it when next taken); foreign-filed issues since last audit brought to template + single `статус:*` + Status = Очередь + «Приоритет»; no subtask or mini-feature; bug-features link their source feature; every Удержание has a hold comment that names what resumes it; every Очередь card has «Приоритет» (set missing ones), except Очередь children of an epic in Удержание, which stay unnumbered; no issue parked in another column for an owner question (questions = pause in place).
3. **Git and PRs:** active remote branches match `type/NN-short-english-slug` ([branches](../elements/git/branches.md)); clean orphans that will not auto-delete (deleting branches other than merged head branches needs the owner); no open PR without an owner and next step; recent PRs have `#NN`, a «Документация» line, finished finding replies; Dependabot rows recorded with `Issue` = `-`, `Stage` = `Dependabot`, PR and sha; a row still `Automations` whose Automations are done is switched to `none` + full review and reviewed now. Flag an open Dependabot PR that has neither a merge path nor a bug issue: a green result needs a row heading to merge (or an owner `Question` where [dependencies](../elements/dependencies.md) requires one); a red result needs a bug issue. Failed runs of «Notify orchestrator» since the last audit (missing secret, non-2xx) are a blocker to report. Do not retrofit closedBy on old closed issues.
4. **Wiki:** no `Doc-` page edited before `main`; no status line treated as truth; sidebar complete; Plan- pages current ([wiki](../elements/wiki/README.md)).
5. **Automations and routines:** every inventory row still Active (Bugbot scope = this repo only); the three routines «TravelAgency CI/CD», `travelagency-memory-refresh` and «Еженедельный аудит порядка» exist and are enabled (missing or disabled = blocker reported to the owner); spot-check 1-2 recent PRs; latest weekly vuln scan run history ([automations](../elements/automations.md)).
6. **Rules:** `.cursor/` consistent with practice; one way of doing each thing; templates match live artifacts.
7. **Memory** current; no hanging cloud agent; stale waits re-checked (agent silence, Deploy catch-up, [repair row](../elements/memory.md#repair-row) observation, Dependabot rows waiting on `Automations`); a row whose `Waiting on` is outside `agent` / `Automations` / `Deploy` / `issue #NN` / `children` / `epic question #NN` / `none`, or whose `Automations` or `Deploy` wait no current webhook can satisfy (superseded head, closed PR with no deploy left), is corrected in this audit. Every row with `Waiting on` = `none`, `Question` = `-` and a concrete `Next` is performed before the audit ends; no column transition on a row whose `Question` is set.
8. **Owner waits:** each non-empty `Question` in memory is listed once in the report with the original question and recommendation (ask again if still unanswered; not a new question; this includes `epic demo`, `create Status «Демо»` and repair rows); a `hold:` ([Удержание](../elements/board/columns/on-hold.md)) is listed with its resume condition and not re-asked ([Question](../elements/memory.md#question)).

## Output
Fix clear reversible drifts at once on work taken or edited since the last audit, and any wrong label, missing «Приоритет» (except children of a held epic) or missing hold reason anywhere ([orchestrator §6](../orchestrator.md#6-powers-act-and-report-vs-ask-first)); older off-template items follow the [in-flight rule](README.md#gates). Send the owner the [weekly audit report](../templates/owner/weekly-audit-report.md). When nothing was found or fixed, the report is one line: «Еженедельная проверка <дата>: замечаний нет.» Otherwise use the full template. Propose rule changes there.
