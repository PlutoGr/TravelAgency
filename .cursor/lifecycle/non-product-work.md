# Non-product work
Process docs, rules, infra, questions. Not a third type and no fake feature page.

- Issue from the [non-product issue template](../templates/github/non-product-issue.md) with a type label (`documentation`, `question`, or `enhancement` for infra) and exactly one `статус:*`.
- Short column list: Очередь → Разработка (while a PR is open) → Приёмка (only when the issue criteria require a dev check) → Готово. Owner questions: pause in place (same column) + [memory](../elements/memory.md). Never use this shorter list for a product feature or bug-feature.
- **Exit without a dev check:** after merge, Deploy does not change the column (it still gates the next merge). When the criteria pass and either the named `Doc-` page is published or the PR «Документация» says «вики не затронута», post the [criteria pass comment](../templates/github/acceptance-comment.md) and close from Разработка by the [close procedure](../elements/board/columns/done.md) (label and Status Готово, then close) in the same turn; if they already pass on the green Deploy wake, close in that wake. Memory around that wake (the Deploy row kept until the green Deploy containing the merge, even after close; before that wake a draft run is only in `Agent` and `Waiting on` stays `Deploy`; after it, `agent` while the draft is live, else `none` with the remaining step) follows the [row lifecycle](../elements/memory.md#row-lifecycle).
- **Exit with a dev check:** green Deploy → Приёмка ([Приёмка](11-deploy-and-acceptance.md)); the criteria pass comment replaces feature case ids; then the same close.
- **`question` issue with no PR:** stays in its column until the answer is recorded («**Итог:** решено: ...» on the issue), then closes the same way (with no PR there is no `Doc-` page to wait for).
- The work is still done by a briefed cloud agent when it touches the repo ([devops](../briefs/devops.md) for infra, [methodology auditor](../briefs/methodology-auditor.md) for rules consistency), and still goes through [review and merge](10-review-and-merge.md).
- Changes of meaning in `.cursor/` need the owner's yes before merge ([orchestrator §6](../orchestrator.md#6-powers-act-and-report-vs-ask-first)).
- Dependabot PRs have no issue ([dependencies](../elements/dependencies.md)). A docs or process PR with no tracker task uses «без задачи» (rare).
- Dependabot red `pr-checks`: open a bug issue from the bug template under the standing backlog ([dependencies](../elements/dependencies.md), [bugs](bugs.md)). That issue then uses the product route for its `Размер` and `Тесты`; do not invent a shortcut. A failed Deploy on `main` follows the [repair](10-review-and-merge.md#repair-while-the-queue-is-stopped) choice (one re-run, or one repair item whose PR is the only merge).
