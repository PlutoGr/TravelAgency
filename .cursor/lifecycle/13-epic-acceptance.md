# 13 Epic completion and owner demo (epic В работе → Демо → Готово)
**Entry:** every issue number listed in the epic's «Разбиение», and every other open child, is Готово (closed). An empty child list is not a finished epic. Do not close the epic on child closes alone. On the last child close, start this stage and set `статус: демо` / Status = Демо in that same turn ([done](../elements/board/columns/done.md)). Until the Project Status option «Демо» exists, the last-child-close turn asks the owner once to create it ([owner question](../templates/owner/owner-question.md)), leaves the epic in `статус: в работе` / В работе, and writes memory `Waiting on` = `owner`, Pause/why = create Status «Демо»; the owner answer that the option exists is one transition: in that turn set `статус: демо` / Status = Демо and run this stage (demo ask, new Pause/why = epic demo). This pause is re-asked like a question. Once the option exists, the same-turn rule stands.

**Who:** the orchestrator prepares the demo; the owner accepts.

**Steps**
1. STOP taking new roadmap work: the next roadmap epic waits until this epic is Готово; in-flight non-roadmap work may continue. Set the epic `статус: демо` and board Status = Демо (same step as the last child close when no siblings remain; while Status «Демо» is missing, the owner-answer turn, see Entry).
2. Send the owner the [epic demo](../templates/owner/epic-demo.md): what shipped (features, `Doc-` and wiki links), how to check on dev, and the checklist: the problem, the chosen user story and the non-goals from «Бизнес и сценарии». Closed children are not enough. In the same turn write memory `Waiting on` = `owner`, `Next` = record accept or gaps, Pause/why = epic demo.
3. Owner pass: close the epic by the [close procedure](../elements/board/columns/done.md) and mark the `Epic-` page «сделано» in the same step (a content mark, not a status). Then epic pick ([02](02-roadmap.md)).
4. Owner finds gaps: set the epic back to `статус: в работе` (memory `Waiting on` = `children`). Related gaps become features or bug-features under this epic, in Очередь with priority. The owner's wording is input to Аналитика, not a skip: the new feature still enters Аналитика; evaluate the proposed fix versus alternatives and bring options if needed. Unrelated discoveries go to the [standing backlog](../project.md#standing-backlog). Repeat this stage after they are done.
5. A child reopened while the epic is in Демо: in the same step set the epic back to `статус: в работе` and Status = В работе ([done](../elements/board/columns/done.md)); repeat this stage once that child is Готово again.

**Interim demo:** the owner may ask for a demo before every child is Готово. Send the [epic demo](../templates/owner/epic-demo.md) marked interim; the epic keeps its column and is not closed. Any interim remark that changes a field, screen or business rule becomes a new feature or bug-feature of this epic: create it in Очередь with «Приоритет», then take it into Аналитика in that turn; the epic column does not change. Record what the owner decided on the epic issue. Full-demo gaps already go through Аналитика (step 4).

The standing backlog (#8) is never closed by child Готово; it stays `статус: очередь` for life. Taking or closing children never moves #8; #8 never enters Демо.

**Exit gate:** recorded owner acceptance («**Итог:** решено: ...» on the epic issue) while in Демо, then Готово.
