# Разработка (`статус: разработка`)
- **Applies to:** feature, bug-feature; non-product issue: PR open, post-merge Deploy wait, and the criteria check when no dev check is needed ([labels](../../issues/labels.md)).
- **Enter:** Крупная product item with `Тесты: сначала сценарии` from Тест-кейсы, or any other product item from Очередь by [take](../../../lifecycle/README.md#take), when «Полное ТЗ» holds ([Разработка](../../../lifecycle/09-development.md)); non-product item from Очередь when taken ([non-product work](../../../lifecycle/non-product-work.md)). An in-flight remap onto this column follows [in-flight](../../../lifecycle/README.md#gates) when the new header tags are still absent.
- **While here:** one cloud agent, one PR; review, findings, merge and the wait for Deploy all stay here ([review and merge](../../../lifecycle/10-review-and-merge.md)). Code review is not a board column and is not Демо.
- **Leave:** → Приёмка after merge and a green Deploy to dev, for a feature, a bug-feature, or a non-product issue whose criteria need a dev check. A non-product issue whose criteria need no dev check: Deploy does not change the column; when its criteria pass and either the named `Doc-` page is published or the PR «Документация» says «вики не затронута», → Готово from here by the [close procedure](done.md). The green Deploy still gates the next merge; the memory row follows the [row lifecycle](../../memory.md#row-lifecycle). Owner question: stay here, `Question` in [memory](../../memory.md#question).
- **Who moves:** orchestrator (label + Status). Deploy readiness arrives via the Deploy webhook or the 60-minute catch-up; a green Deploy whose deployed sha contains the row's match sha advances the item ([Deploy wait](../../../lifecycle/events.md#deploy-wait), [row lifecycle](../../memory.md#row-lifecycle)).
- **Required:** branch linked, PR with «Задача» `#NN` and «Документация» line, wait row in [memory](../../memory.md) after merge.
