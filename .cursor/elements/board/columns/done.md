# Готово (`статус: готово`)
- **Applies to:** all.
- **Enter:** feature or bug-feature after Приёмка passed and either the named `Doc-` page is published or the PR «Документация» says «вики не затронута»; non-product issue when its acceptance criteria are met and the same `Doc-` condition holds, from Приёмка when its criteria need a dev check, otherwise from Разработка or, for a `question` issue with no PR, from the column where the answer was recorded ([non-product work](../../../lifecycle/non-product-work.md)); epic after owner acceptance in Демо; any item closed as not planned. [Doc- after merge](../../../lifecycle/12-docs-after-merge.md) never blocks Готово when no `Doc-` page was named.
- **Close procedure:** the orchestrator first sets `статус: готово` (removes other status labels) and sets board Status to Готово, **then** closes the issue (`gh issue close <NN>`, with `--reason "not planned"` when cancelled). Never leave an open issue with `статус: готово`. The close comment ([status comments](../../../templates/github/status-comments.md)) names the only reopen column: an item closed as not planned (any type, including a cancelled epic) → Очередь; otherwise a feature or bug-feature that reached Приёмка → Приёмка; a non-product issue → the column it closed from; an epic accepted from Демо → В работе. On reopen, the orchestrator sets that column (label and Status) and writes its [memory](../../memory.md) row in the same turn. Reopen into Приёмка restores the [Sha cell](../../memory.md#sha-cell) (`entry`, `fix`) from the merged PR(s); if the latest successful deployed sha does not contain the match sha, the issue enters Разработка instead with `Waiting on` = `Deploy`, `Next` = re-enter Приёмка. An epic accepted from Демо: if every child is still Готово, run the [epic demo](../../../lifecycle/13-epic-acceptance.md) in that same turn (Демо, demo ask, `Question` = `epic demo`); if a child was reopened with it, В работе with `Waiting on` = `children`. When the reopened issue is a child of a product epic in Демо, the same step sets that epic back to `статус: в работе` and Status = В работе, `Waiting on` = `children`, clears the epic's `epic demo` `Question` and sets `Next` = run Демо when that child is Готово again ([Question guard](../../memory.md#question-guard) exception (a)). In the same step mark the wiki page (below), and resume every [memory](../../memory.md) row with `Waiting on` = `issue #NN` for the closed issue: set it to `none` and perform its `Next` in this turn (for example resume the parent's acceptance), subject to the [Question guard](../../memory.md#question-guard); the closed issue's own row is deleted by the [row lifecycle](../../memory.md#row-lifecycle). When a **child** closes (this is the step that resumes the epic's `children` row): if any sibling of that product epic is still open, set (or keep) the epic `статус: в работе` and Status = В работе with `Waiting on` = `children`; if none remain, start the [epic demo](../../../lifecycle/13-epic-acceptance.md) and set the epic `статус: демо` / Status = Демо in that same turn (do **not** always write В работе). Exceptions, in this order: when the epic's `Question` is already set, keep it and do not enter Демо ([Question guard](../../memory.md#question-guard); enter Демо in its answer turn if every child is still Готово); otherwise, when the Project Status option «Демо» is missing, set `Question` = `create Status «Демо»` and keep the epic in В работе. This epic update applies only when the epic is already in В работе or Демо; an epic still in Разбиение stays there until a child is taken, or until the split is explicitly abandoned and the epic is closed as not planned from Разбиение. The standing backlog (#8) never changes column on child take or close.
- **On close:** `.github/workflows/link-closed-by.yml` sets the PR chip. Do not add `closes`/`fix`/`fixes`, do not call `addCloseIssueReferences`, do not add or remove Development links (carve-out: the owner explicitly asks). A follow-up comment may note the merged PR.
- **Wiki:** in the same step as the close, the `Feature-` page gets «сделано» with links (`Doc-`, ADR, PRs); the `Epic-` page gets it only at owner acceptance; cancelled work gets «отменено» with the reason. This is the only moment for these marks.
- **Who moves:** orchestrator.
