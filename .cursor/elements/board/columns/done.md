# Готово (`статус: готово`)
- **Applies to:** all.
- **Enter:** feature or bug-feature after Приёмка passed and either the named `Doc-` page is published or the PR «Документация» says «вики не затронута»; non-product issue when its acceptance criteria are met and the same `Doc-` condition holds, from Приёмка when its criteria need a dev check, otherwise from Разработка or, for a `question` issue with no PR, from the column where the answer was recorded ([non-product work](../../../lifecycle/non-product-work.md)); epic after owner acceptance in Демо; any item closed as not planned. [Stage 12](../../../lifecycle/12-docs-after-merge.md) never blocks Готово when no `Doc-` page was named.
- **Close procedure:** the orchestrator first sets `статус: готово` (removes other status labels) and sets board Status to Готово, **then** closes the issue (`gh issue close <NN>`, with `--reason "not planned"` when cancelled). Never leave an open issue with `статус: готово`. The close comment ([status comments](../../../templates/github/status-comments.md)) names the reopen column: a feature or bug-feature that reached Приёмка → Приёмка; a non-product issue → the column it closed from; an epic → В работе; an item closed as not planned → Очередь. On reopen, the orchestrator sets that column (label and Status) and writes its [memory](../../memory.md) row in the same turn; when the reopened issue is a child of a product epic in Демо, the same step sets that epic back to `статус: в работе` and Status = В работе (the demo is repeated after the child is Готово again, [stage 13](../../../lifecycle/13-epic-acceptance.md)). In the same step mark the wiki page (below), and resume every [memory](../../memory.md) row with `Waiting on` = `issue #NN` for the closed issue: set it to `none` and perform its `Next` in this turn (for example resume the parent's acceptance). When a **child** closes: if any sibling of that product epic is still open, set (or keep) the epic `статус: в работе` and Status = В работе; if none remain, start [stage 13](../../../lifecycle/13-epic-acceptance.md) and set the epic `статус: демо` / Status = Демо in that same turn (do **not** always write В работе); until the Project Status option «Демо» exists, ask the owner once to create it and keep the epic in В работе with `Waiting on` = `owner` (stage 13). This epic update applies only when the epic is already in В работе or Демо; an epic still in Разбиение stays there until a child is taken, or until the split is explicitly abandoned and the epic is closed as not planned from Разбиение. The standing backlog (#8) never changes column on child take or close.
- **On close:** `.github/workflows/link-closed-by.yml` sets the PR chip. Do not add `closes`/`fix`/`fixes`, do not call `addCloseIssueReferences`, do not add or remove Development links (carve-out: the owner explicitly asks). A follow-up comment may note the merged PR.
- **Wiki:** in the same step as the close, the `Feature-` page gets «сделано» with links (`Doc-`, ADR, PRs); the `Epic-` page gets it only at owner acceptance; cancelled work gets «отменено» with the reason. This is the only moment for these marks.
- **Who moves:** orchestrator.
