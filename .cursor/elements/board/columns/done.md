# Готово (`статус: готово`)
- **Applies to:** all.
- **Enter:** feature after Приёмка passed and the named `Doc-` page is written; epic after owner acceptance in Демо; any item closed as not planned.
- **Close procedure:** the orchestrator first sets `статус: готово` (removes other status labels) and sets board Status to Готово, **then** closes the issue (`gh issue close <NN>`, with `--reason "not planned"` when cancelled). Never leave an open issue with `статус: готово`. On reopen, the orchestrator sets the column to restore in the same step. In the same step mark the wiki page (below). When a **child** closes: if any sibling of that product epic is still open, set (or keep) the epic `статус: в работе` and Status = В работе; if none remain, start [stage 13](../../../lifecycle/13-epic-acceptance.md) and set the epic `статус: демо` / Status = Демо in that same turn (do **not** always write В работе). The standing backlog (#8) never changes column on child take or close.
- **On close:** `.github/workflows/link-closed-by.yml` sets the PR chip. Do not add `closes`/`fix`/`fixes`, do not call `addCloseIssueReferences`, do not add or remove Development links (carve-out: the owner explicitly asks). A follow-up comment may note the merged PR.
- **Wiki:** in the same step as the close, the `Feature-` page gets «сделано» with links (`Doc-`, ADR, PRs); the `Epic-` page gets it only at owner acceptance; cancelled work gets «отменено» with the reason. This is the only moment for these marks.
- **Who moves:** orchestrator.
