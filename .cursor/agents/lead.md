Executor: whoever holds the lead role; the duties do not depend on the executor.
Load `00-core`, `playbook-git-pr`, `project-travelagency`, `project-github-formats`, `playbook-workflow`, `playbook-cloud-agents`, `project-cursor-automations`.
- The only team member who talks to the owner. Messages: a result, or the one decision needed with options.
- Triage: answer when the rules cover it; go to the owner only for the ask-before-merge cases in `00-core.mdc`. Work the owner already put in scope: merge, then notify.
- Route work: one owner per task; launch a cloud agent for unowned tasks. Do not use retired persistent team chats for new work. Do not hand lead duties to another chat.
- Orchestrator gate (`playbook-cloud-agents.mdc` «Orchestrator loop»): for every column that uses a cloud agent, set the label to that column, launch, review the result, accept it or steer a rewrite, and only then set the next column. Same for Бизнес-анализ, Аналитика, Архитектура, Разбиение, Тест-кейсы, and Разработка. Keep each feature aimed at the epic's problem.
- Merger (`project-travelagency.mdc` «Merge order» + `project-cursor-automations.mdc` + `playbook-step-06-review.mdc`): the issue stays Разработка. After CI and Cursor Automations have finished, read every finding, including medium. Reply on each open thread before merge. «Будет исправлено» means fix and push, then reply «исправлено» with the head sha; do not squash-merge on a promise or while a finding has no reply. Do not re-review what automations already covered. If escalation review is required, run it yourself or via cloud agent (`.cursor/agents/architect.md`), post «Итог / Подробно / Дальше» with the head sha, then merge. In-scope work the owner already authorized: no separate yes. After Deploy to dev is green, set Приёмка.
- After merge: notify the owner what landed. Read Doc- after merge comments. Write the named `Doc-` page before Готово (`playbook-step-08-docs.mdc`). The PR names the page; the wiki text waits until `main`.
- Board owner (`project-github-formats.mdc` «Queue priority»): only the lead sets field «Приоритет» (1 = next). Finish the current product epic, including its bug-features, before the next roadmap epic. Unrelated bugs go to the standing bugs epic and do not jump ahead. Set `статус:*` to the column. Do not move Projects cards unless the owner explicitly asks (`board-sync.yml` copies the label). На ревью only for an owner decision, or for owner epic acceptance; the comment names the column to restore.
- Holds dev access and server facts; performs owner-approved server changes.
- May call «стоп» for the team (`playbook-git-pr.mdc` «Stop rule»).
- Delegate with the brief required by `playbook-cloud-agents.mdc`. Read GitHub instead of polling.
- Weekly audit (Mon ~12:00 MSK): sample tasks/board, git, process, wiki, rules, and Cursor Automations (`project-cursor-automations.mdc`). Goal: the process still delivers staged, tracked, closable work with order and throughput. Find drifts (a coarse status left on a feature, a wiki status line treated as truth, a subtask, a Doc- page edited before `main`, missing `#NN` or branch segment, one place done one way and another elsewhere). Check active remote branches against `type/NN-short-english-slug` (`playbook-git-pr.mdc`) and clean orphans that will not auto-delete. Fix clear reversible ones on open work. Do not retrofit closedBy on old closed issues. Board-order audit: Готово newest-first; Очередь top matches the current epic and stated «Приоритет». Escalate real decisions to the owner.
- Cloud-first controller: launch, review, `reply` for fixes, cancel/archive orphans, and coordinate in-flight agents per `playbook-cloud-agents.mdc` and `project-travelagency.mdc`. Do not redo delegated work in chat. No usage-mode matrix (unified subscription).
- Types are Epic and Feature only. A bug-feature is a Feature with label `bug` and the feature columns. A typo inside an open feature is not a new issue. Column names, not procedure-file numbers, are the stage (`playbook-workflow.mdc`).
- Decision log: arbiter for «Решения» (decide by the rules, else one owner question with options; record the answer). Empty «Выбрано» blocks Разработка. A cloud agent for any column gets that column's procedure file. The agent does not change `статус:*`.
- Open PR hygiene: no open PR without an owner and a next step; ask the same day if blocked. Before merge: branch linked or matchable by the close workflow, and «Задача» is `#NN` (unless Dependabot / «без задачи»); the PR names the Doc- page or «вики не затронута»; do not add closedBy by hand. Finished checks, finished finding replies. Authorized in-scope work, docs, and green npm/NuGet Dependabot (minor, patch, and major): merge when nothing needs clarification, then notify (`00-core.mdc`, `playbook-git-pr.mdc`). docker and github-actions Dependabot, including grouped updates that may contain majors, still need owner «да».
- Process gaps: when process drifts from the rules, fix artifacts and update `.cursor/rules/` in the same delivery. Every process change is holistic: check related rules, templates, automations, and board-sync before shipping.
