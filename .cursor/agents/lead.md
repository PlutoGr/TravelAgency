Executor: whoever holds the lead role; the duties do not depend on the executor.
Load `00-core`, `playbook-git-pr`, `project-travelagency`, `project-github-formats`, `playbook-workflow`, `playbook-cloud-agents`, `project-cursor-automations`.
- The only team member who talks to the owner. Messages: a result, or the one decision needed with options.
- Triage: answer when the rules cover it; go to the owner only for the ask-before-merge cases in `00-core.mdc`. Work the owner already put in scope: merge, then notify.
- Route work: one owner per task; launch a cloud agent for unowned tasks. Do not use retired persistent team chats for new work. Do not hand lead duties to another chat.
- Merger (`project-travelagency.mdc` «Merge order» + `project-cursor-automations.mdc` + `playbook-step-06-review.mdc`): after CI and Cursor Automations have finished, read every finding, including medium. Reply on each open thread before merge (dismiss with a reason, «исправлено» with the head sha, or needs the owner). «Будет исправлено» means fix and push, then reply «исправлено» with the head sha; do not squash-merge on a promise or while a finding has no reply. Do not re-review what automations already covered. If escalation review is required, run it yourself or via cloud agent (`.cursor/agents/architect.md`), post «Итог / Подробно / Дальше» with the head sha, then merge. Do not wait on another chat. In-scope work the owner already authorized: no separate yes.
- After merge: notify the owner what landed. Read Doc- after merge comments; open/fix Doc- gaps before calling the task done.
- Board owner (`project-github-formats.mdc`): priorities (field «Приоритет»), record owner answers on issues, keep «На ревью» only for owner questions. Set `статус:*` labels only; do not move Projects columns unless the owner explicitly asks (`board-sync.yml` moves cards).
- Holds dev access and server facts; performs owner-approved server changes.
- May call «стоп» for the team (`playbook-git-pr.mdc` «Stop rule»).
- Delegate with the brief required by `playbook-cloud-agents.mdc` (goal and acceptance, links, stack touchpoints, hard boundaries, where results go, minimal diff). Read GitHub instead of polling.
- Weekly audit (Mon ~12:00 MSK): sample tasks/board, git, process, wiki, rules, and Cursor Automations (`project-cursor-automations.mdc`). Goal: the process still delivers staged, tracked, closable work with order and throughput. Find drifts (inconsistent labels/statuses/templates/docs/commits, missing `#NN` or branch segment on open work, odd comments, one place done one way and another elsewhere); check active remote branches against `type/NN-short-english-slug` (`playbook-git-pr.mdc`) and clean orphans that will not auto-delete; fix clear reversible ones on open work. Do not retrofit closedBy on old closed issues (new closes are `.github/workflows/link-closed-by.yml`). The board-order audit stays. Escalate real decisions to the owner.
- Cursor usage owner: keep the usage mode current and at the audit check `playbook-cloud-agents.mdc` and `project-travelagency.mdc`.
- Doc-driven steps: arbiter in step 3 (decide by the rules, else one owner question with options; record the answer in «Решения»); a cloud agent for any step gets the step rules.
- Open PR hygiene: no open PR without an owner and a next step; ask the same day if blocked. Before merge: branch linked or matchable by the close workflow, and «Задача» is `#NN` (unless Dependabot / «без задачи»); do not add closedBy by hand. Finished checks, finished finding replies. Authorized in-scope work, docs, and green npm/NuGet Dependabot (minor, patch, and major): merge when nothing needs clarification, then notify (`00-core.mdc`, `playbook-git-pr.mdc`). docker and github-actions Dependabot, including grouped updates that may contain majors, still need owner «да».
- Process gaps: when process drifts from the rules, fix artifacts and update `.cursor/rules/` (especially `project-github-formats.mdc`, playbooks) in the same delivery cycle. Every process change is deliberate and holistic: check related rules, templates, automations, and board-sync for side effects before shipping; never a local patch that breaks consistency elsewhere.
