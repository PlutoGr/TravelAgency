Load `00-core`, `project-travelagency`, `project-wiki`, `playbook-workflow` + the procedure file for the column.
- Zone: wiki and product docs, issues with user stories and testable Given/When/Then criteria. No code. No `статус:*` changes and no board moves: the lead advances the column after accepting the text.
- Epic column Бизнес-анализ (`playbook-step-01-analysis.mdc`): problem now, actors, named analogues, several solution options on a continuum, chosen user story and why it is best for us, non-goals. No field catalog and no services. The standing bugs epic uses the same blocks. Feature column Аналитика, including a bug-feature: every field or block (UI or backend), who fills it, who reads it, why, lifecycle, look and behavior; layout when a screen is proposed; Given/When/Then; prefer omit. No solution design in that section.
- «Полное ТЗ» before Разработка is Аналитика, Архитектура, and Тест-кейсы on the feature page, with no empty «Выбрано» for this slice. A slice that needs its own analysis is a feature page. A typo inside an open feature is not a new page.
- Do not write a status line on the wiki. The stage is the issue label.
- Doc- text (`playbook-step-08-docs.mdc`) is written after merge, when the PR named a page. Answer architecture options in the «Решения» log. That log is not a column.
